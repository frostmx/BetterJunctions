# BetterJunctions

Серверный C++-мод для Satisfactory: чинит ванильную пробку самоходных траков на перекрёстках.
Ассетов нет, клиентской части нет (`RequiredOnRemote: false`), ставится только туда, где живёт
авторитет — на выделенный сервер или хосту.

## Что ломается в ванили

Автопилот бронирует «блоки пути» перекрёстка на дистанцию торможения вперёд
(`UFGVehicleAutopilotComponent::CalculatePathReservationStopTarget`). Эта дистанция не
останавливается на траке, который едет впереди: второй в очереди бронирует блоки перекрёстка,
в который первый ещё только пытается въехать, а потом встаёт за первым по vehicle-avoidance.
Первый не может взять свою последовательность блоков — резерв второго пересекается с ней, —
а второй ничего не отпускает: он ждёт *трак*, а не *блок*, и встроенный 120-секундный
deadlock-таймер (`mAutopilotWaitTimeToDeadlock`) на него не распространяется. Все остальные
полосы перекрёстка встают за одним из этих двух.

Замер 12.09.2026: 29 траков, четыре полосы, один резерв (`Build_VehiclePath_Universal_C_2147435657`,
блок #1) у трака, стоявшего вторым. Снятие этого резерва (выключить/включить автопилот) распустило
три полосы за три секунды, четвёртую — как только слилась первая.

## Что делает мод

Два хука SML, оба только на авторитете:

- **Профилактика.** Пре-хук `ReserveVehiclePathBlocks_Parallel` — единственного места, где
  блоки бронируются. Если впереди стоит трак (vehicle-avoidance цель со скоростью < 1 м/с), из
  списка на бронирование выкидывается всё, что начинается дальше него
  (`CalculateTotalDistanceBetweenPathBlocks` от текущего блока). Список ещё и наполняет набор
  «нужных» блоков, по которому игра сама чистит лишние резервы, так что уже удержанные блоки за
  лидером отпускаются в тот же тик. Первая версия резала lookahead в
  `CalculatePathReservationStopTarget` — замер показал, что на бронирование это не влияет:
  трак в 5 см за стоящим всё равно брал блок перекрёстка через два блока от себя. Движущийся
  лидер намеренно не трогается.
- **Лечение.** Пост-хук `AFGVehicleSubsystem::TickVehicleAutopilot`: трак, который 5 секунд стоит
  за стоящим траком и держит резервы, их отпускает (`ReleaseVehiclePathBlockReservations_Parallel`),
  один раз за эпизод стояния. После сброса профилактика не даст снова забронировать дальше лидера,
  а короткие резервы до него держат место в очереди.

Оба метода protected — доступ через friend-трансформер (`Config/AccessTransformers.ini`), поэтому
любая сборка мода пересобирает `FactoryGame` целиком.

## Консоль

- `BJ.Dump` — все траки на автопилоте: статус, скорость, время ожидания блока, число резервов,
  стоп-цель, сколько стоит за стоящим.
- `BJ.Unstick` — снять резервы у всех, кто прямо сейчас стоит за стоящим, без 5-секундной задержки.
- `BJ.Blocks [фильтр]` — все резервы прямо из массивов блоков сегментов (рефлексии они не видны):
  эксклюзивные с владельцем, shared с тем эксклюзивом, которому принадлежат, и пометка GHOST у
  тех, на которые никто больше не ссылается.
- `BJ.Purge` — снять все призрачные резервы, найденные тем же обходом.
- `Log LogBetterJunctions Verbose` — печатать каждое урезание списка на бронирование.

## Сборка

Правила как у любого C++-мода: редактор закрыт, `-KeepEditor` неприменим. Первая упаковка нового
мода падает на куке (нет `UnrealEditor-BetterJunctions.dll`, alpakit передаёт `-nocompileeditor`) —
один раз собрать таргет `FactoryEditor`, дальше:

```
pwsh -NoProfile -ExecutionPolicy Bypass -File C:\Users\frost\SF_server\alpakit-dev.ps1 -ModName BetterJunctions -NoDeploy
```

## Проверка

Пробку воспроизвести трудно; проверять надо от обратного. `BJ.Dump` на живом сервере не должен
показывать трак с `reservations > 0`, `speed 0` и стоп-целью «vehicle … at 0 cm/s» дольше пяти
секунд. В логе `LogBetterJunctions` каждое такое снятие печатается с именем трака.
